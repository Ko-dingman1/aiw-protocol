# v0.3 — validation, history and bounded queries

All packages are 0.3.0 and descriptors use protocolVersion 0.3. Upgrade registry, node and client together. Older Git tags retain earlier behavior.

| Operation   | Endpoint                          | Behavior                                                       |
| ----------- | --------------------------------- | -------------------------------------------------------------- |
| Catalog     | GET /schemas                      | Advertised domain schemas                                      |
| Schema      | GET /schemas/:id                  | JSON Schema for domain fields plus cross-field constraints     |
| Exact fetch | GET /objects/:id?version=1        | Retained version; omit version for latest                      |
| History     | GET /objects/:id/history          | Descending versions, retention limit, oldest available version |
| Verify      | GET /objects/:id/verify?version=1 | Metadata and exact retained reference audit                    |
| Query       | POST /query                       | Filters plus schema, limit (1–100, default 50), cursor         |

Responses to query are {objects, nextCursor?}. Opaque base64url cursors bind to normalized filters; they are positions, not credentials or signatures. Keep filters unchanged; page size may change. IDs use JavaScript string ordering. Pages form a live keyset view, not a snapshot: concurrent insertion before a cursor will not appear, and values may change between pages. Start again for a fresh view.

The client query() follows all pages, iterate() yields objects incrementally, and queryPage() exposes explicit pages. history(), fetch(id, version), schemas() and verify(id, version) expose the new operations.

## Domain validation

The built-in catalog validates Celsius temperature, nonnegative KRW price, nonnegative integer employee count and ordered employee ranges. Unknown schema IDs fail closed at ingestion. The range constraint minimum <= maximum is enforced in TypeScript and disclosed in the document, alongside JSON Schema. This is a small local catalog, not a remotely writable registry or full ontology. Checks establish neither factual truth nor provider authenticity.

## History and memory

Defaults: 100 versions per ID, 1,000 IDs, 64 KiB per serialized object, 16 MiB total serialized retained data. JavaScript object overhead is additional. The oldest version of an ID is pruned at its version limit. All data is lost on restart. Inputs and outputs are copied so caller mutations cannot rewrite history.

Exact retries of identical retained objects are idempotent. Same-version changed content, lower versions and changed object identity fail with AIW_VERSION_CONFLICT (409). Version gaps are allowed. Missing IDs return 404. An absent requested version returns AIW_VERSION_UNAVAILABLE (410), whether unpublished or pruned. Capacity failures use AIW_RESOURCE_LIMIT (413) without partial writes.

Verification checks direct derivation/evidence/provenance references against retained exact versions. Missing/pruned inputs cause explicit failure. It does not recursively verify a whole graph, detect all cycles, authenticate publishers or decide truth.

## Dashboard and demo

The inspector provides history selection, a pinned historical view, return-to-latest, exact derivation navigation, server verification and domain rules. SSE cannot overwrite a pinned historical selection. Browser queries follow pages.

Run pnpm demo:reliability for invalid-unit rejection, original/latest values, retained history, conflicts across pages and derivation inputs surviving updates. pnpm dev runs the offline dashboard; pnpm dev:live optionally uses external weather.

Authentication, persistence, multi-node trust, metrics and production load/security testing remain future work. See completion-criteria.ko.md for portfolio and production criteria.
