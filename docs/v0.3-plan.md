# v0.3 plan and acceptance criteria

Scope: make the existing local research prototype easier to trust and reproduce. Keep HTTP, in-memory storage, optional Open-Meteo and offline demos.

1. Add a small domain-schema catalog for the four existing schema IDs. Validate values, units, namespace and property at ingestion; reject unknown schemas. Expose machine-readable catalog documents. This is domain validation, not truth verification.
2. Retain immutable object versions with explicit memory limits. Fetch exact versions, list retained history, reject conflicting rewrites, and make retention expiry visible.
3. Bound query responses with keyset pagination. Bind cursors to filters; preserve client query() through automatic iteration. Document live-page consistency.
4. Add dashboard history browsing and server verification of exact references. Resolve inputs from retained versions, not just currently loaded objects.
5. Add regression/integration tests, a reproducible reliability demo, migration docs and Korean/English release notes. Run install/typecheck/lint/test/build/demos and hosted CI before the version tag.

Completion means the promised behavior is implemented, failure paths are tested, docs describe the actual limits, and a fresh checkout runs successfully. No feature count establishes perfection. Authentication, persistent storage/backups, multi-node trust policy, operational metrics, load testing and public deployment remain separate production requirements.
